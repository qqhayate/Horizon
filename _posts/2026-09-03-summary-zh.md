## [Claude Fable/Mythos 5.1：新 SOTA 模型，缓存降价 75%，输出词元涨价 70%](https://www.latent.space/p/ainews-claude-fablemythos-51-new) ⭐️ 9.0/10

Anthropic 发布了 Claude Fable/Mythos 5.1，并将其定位为新的 SOTA 模型。此次发布将提示缓存（prompt cache）价格下调 75%，同时将输出词元价格上调 70%。 这意义重大：Anthropic 推出新一代前沿模型会重置 LLM 市场的竞争标杆，影响开发者、企业和竞争对手。定价调整改变了大量依赖长提示词的 AI Agent 等应用的成本结构，使缓存密集型任务大幅降价，但生成式输出的成本上升。 75% 的缓存降价适用于 Anthropic 的 prompt caching 定价，即复用近期已见输入词元的成本，而 70% 的输出词元涨价指的是生成内容的每词元价格。最终成本取决于使用场景：以读取缓存上下文为主的应用会受益，而以长文本生成为主的任务可能面临明显涨价。

rss · Latent Space · 9月2日 07:46

**背景**: 大语言模型会把文本切分成称为“词元（token）”的处理单元，词元可以是单词、词的一部分或标点；API 通常按输入给模型和由模型生成的词元数量计费。Prompt caching 是一种 API 功能，允许开发者复用最近出现过的输入词元来降低成本和延迟，例如 OpenAI 的 prompt caching 为缓存输入提供 50% 折扣。由于 AI Agent 经常反复发送相同的大量指令，缓存折扣可能大幅改变一个系统的运营成本。

## [Paint.NET 借助 Claude 重写 Direct2D 支持 Wine，18 万行 AI 代码引热议](https://simonwillison.net/2026/Sep/2/rick-brewster/) ⭐️ 8.0/10

Rick Brewster 透露，Paint.NET 现在内置了一个从零开始、采用洁净室逆向工程方式重写的 Direct2D 实现，用于在 Wine 上运行，通过 /wine 参数启用，并打包为 PaintDotNet.Windows.Direct2D1.Managed.dll。这约 18 万行代码大部分由 Anthropic 的 Claude 模型编写。 Direct2D 一直是 Paint.NET 在 Linux 上的 Wine 环境中运行的最大障碍，因此这项工作打通了 Windows 到 Linux 兼容性的主要堵点。它还展示了 AI 辅助洁净室逆向工程在如此大规模下的可行性，并引发了更广泛的行业问题：未经充分审查、由 AI 生成（即“氛围编程”）的代码在多大程度上可以信任。 Brewster 明确表示这些代码属于“氛围编程”（vibe coding），没有经过彻底审查，因为 18 万行代码远远超出一个人能仔细检查的量。他不得不持续监督 Claude，纠正诸如缺少 COM 引用计数（相当于 AddRef）的错误和糟糕的架构决策，同时也对 Claude 逆向推导 Direct2D 内置特效库所需公式的能力感到印象深刻。

rss · Simon Willison · 9月2日 05:50

**背景**: Direct2D 是微软为 Windows 提供的硬件加速、即时模式 2D 图形 API，Paint.NET 用它来渲染界面和图像。Wine 是一个兼容层，能让 Windows 应用程序在 Linux 上运行，但 Wine 对 Direct2D 的支持长期不完整，这成为 Paint.NET 迁移的主要障碍。洁净室逆向工程是指仅根据公开行为还原某项技术的功能，而不复制其原始代码，这种做法具有明确的法律先例。“氛围编程”（vibe coding）则指用户用自然语言描述需求、由 AI 助手自动生成代码，而不是手动逐行编写。
