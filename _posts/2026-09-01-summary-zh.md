## [NAT 的“原罪”：Linux NAT 实现者反思互联网中心化](https://dreamstation.systems/personal/ntppost.html) ⭐️ 8.0/10

博客文章《互联网中心化与 NAT 的原罪》提出，NAT 是互联网从开放、点对点模式转向客户端-服务器模式的关键推手；该文在 Hacker News 上获得 177 分和 139 条评论，部分原因是 Linux NAT 系统的原始实现者 Rusty Russell 亲自参与讨论，提供了第一手背景。Russell 回忆说，他当时优先考虑把一个 IP 地址塞进更多连接，而不是保留公网端点。 这件事之所以重要，是因为它把 NAT 从“中立的 IPv4 地址节约工具”重新定义为一种决定性的架构力量，推动了互联网走向客户端-服务器模式以及当今以云为中心的格局。同时，它让人们罕见地看到 Linux NAT 编写者的思考与遗憾，为当前关于 IPv6 推广、CGNAT（运营商级 NAT）和恢复点对点能力的讨论提供了参考。 Rusty Russell 称，他在 Linux 中实现现行 NAT 系统时选择不做端口预留，以便把更多连接挤进同一个 IP 地址；这样做导致来自不同远程地址的入站流量无法路由，主机因此失去了公网端点。文章还提到，NAT 最早于 1994 年在 RFC 1631 中正式提出，早于现代 Web 的爆发式增长。

hackernews · robinpie · 8月31日 02:23 · [社区讨论](https://news.ycombinator.com/item?id=49504905)

**背景**: 网络地址转换（NAT）通过在 IP 数据包头中改写地址信息，将私有 IP 地址空间映射到另一个地址空间，从而让本地网络中的多台设备共享一个公网 IPv4 地址。它很大程度上是为了缓解 IPv4 地址不足而引入，后来被内置到家用路由器中，导致除非配置端口转发或 UPnP，否则消费者设备在外部网络中不可达。这个技术折衷被普遍认为是早期开放、点对点互联网——任何人只要公布自己的地址就能运行服务器——最终让位于“设备只与云端对话”这一模式的原因之一。

## [通过 AD CS RPC 从 IIS 应用程序池提升至 SYSTEM 权限](https://www.reddit.com/r/netsec/comments/1w36tcq/privilege_escalation_from_iis_apppool_to_nt/) ⭐️ 8.0/10

一名安全研究人员公开了一种权限提升技术，通过滥用 Active Directory 证书服务（AD CS）的 RPC 端点，将 IIS 应用程序池身份提升至 NT Authority/SYSTEM。具体的利用细节在链接的研究文章中给出，但 Reddit 帖子本身没有附加说明文字。 这是一条在 Windows 企业环境中具有高价值的提权路径，因为 IIS 应用程序池账户通常用于运行 Web 应用，而获得 SYSTEM 权限将使攻击者完全控制主机。该技术揭示了涉及 AD CS RPC 接口的新型滥用原语，若未及时修补或加固，可能会影响许多组织。 该提交仅为链接形式，因此帖子中未说明具体的 CVE 或漏洞编号、受影响的 AD CS 版本以及利用机制。该技术很可能针对 AD CS 暴露的证书注册或登记 RPC 接口，这些接口可从本地网络或通过 IIS 托管的应用程序访问。

reddit · r/netsec · /u/1046ica · 8月31日 07:40

**背景**: Active Directory 证书服务（AD CS）是 Windows Server 的一个角色，用于在 Active Directory 域内提供公钥基础设施（PKI），以签发、管理和吊销数字证书。IIS 应用程序池标识是 Internet Information Services（IIS）用来运行工作进程的虚拟账户，通常具有受限权限。远程过程调用（RPC）是一种协议，允许程序通过网络向另一个程序请求服务；AD CS 暴露了多个用于证书管理的 RPC 端点，若未加以保护，可能成为攻击面。

## [Claude 共享链接遭搜索引擎索引，用户隐私大面积泄露](https://t.me/zaihuapd/43511) ⭐️ 8.0/10

Anthropic 的 Claude 共享链接功能存在严重隐私漏洞，生成的公开链接未设置 noindex 标签，导致 Google 等搜索引擎可以索引对话内容。包含 API 密钥、加密货币钱包、个人简历、律师咨询记录和社会安全号码等敏感信息的对话已可被公开搜索到。 这是一起重大隐私泄露事件，任何能上网的人都能获取高度敏感的用户数据，而 Anthropic 目前尚未修复。该问题与大约一年前 ChatGPT 遭遇的类似问题如出一辙，对 AI 产品用户和开发者都具有重要警示意义。 泄露的数据包括 API 密钥、加密货币钱包、个人简历、律师咨询记录、公司内部项目资料以及社会安全号码。Anthropic 尚未解决该问题，建议用户手动进入设置中的“共享对话”管理页面，删除涉及个人隐私或财务的聊天记录。

telegram · zaihuapd · 8月31日 03:22

**背景**: 搜索引擎会使用自动爬虫发现并索引网页，而 noindex 元标签或 X-Robots-Tag 响应头可以指示它们不要索引某个页面。当共享链接缺少此类标签时，对话就可能出现在搜索结果中。大约一年前，ChatGPT 出现过类似问题并迅速修复，凸显了 AI 协作功能中索引控制的重要性。
